|---|---|---|

| ทั้งเครื่องเซิร์ฟเวอร์ | Hostinger VPS backup อัตโนมัติ | สัปดาห์ละครั้ง · กู้ ~3.7 ชม. ย้อนทั้งเครื่อง |

ตั้งค่าอยู่ที่ Dokploy → SE SURVEY → **supabase** → แท็บ **Backups** (ปลายทาง `r2-backup` ใน Settings → S3 Destinations)
ไฟล์เป็น `pg_dump` แบบ custom format ที่บีบด้วย gzip (PostgreSQL 15.8) — ชุดแรก 24/09/69 ขนาด 1.9 MB

## ดูว่าสำรองยังเดินอยู่
- Dokploy → supabase → Backups → ไอคอนรายการ (📋) ที่แถว `db` = ประวัติการสำรอง
- หรือเปิด Cloudflare → R2 → bucket `backup` ต้องมีไฟล์ของเมื่อคืน
- กดปุ่ม ▷ ที่แถว `db` = สำรองทันที 1 ชุด (ทำก่อนแก้ข้อมูลครั้งใหญ่/ก่อนรัน migration ทุกครั้ง)

## กู้เมื่อเกิดเหตุ — เลือกตามกรณี

**ก. ข้อมูลบางส่วนผิด/หาย (ระบบยังใช้ได้)** — ห้ามกู้ทับทั้งฐาน เพราะงานที่ทำหลังเวลาสำรองจะหายหมด
ให้นักพัฒนากู้ไฟล์ลงฐานทดลองแยก (วิธีในหัวข้อ "ทดสอบกู้" ด้านล่าง) แล้วคัดเฉพาะแถวที่ต้องการกลับเข้าฐานจริง
เคสที่เผลอลบในเว็บ กู้จากถังขยะหน้าแอดมินได้ภายใน 30 วัน ไม่ต้องใช้ไฟล์สำรอง

**ข. ฐานข้อมูลพัง/หายทั้งก้อน (เซิร์ฟเวอร์ยังอยู่)**
1. ถ้าฐานยังเปิดได้บางส่วน กด ▷ สำรองสภาพปัจจุบันเก็บไว้ก่อน
2. Dokploy → supabase → Backups → **Restore Backup** → ปลายทาง `r2-backup` → เลือกไฟล์ล่าสุดก่อนเกิดเหตุ → ฐาน `postgres` → ยืนยัน
   ⚠️ ทับข้อมูลในฐานทั้งหมด · ปุ่มนี้ยังไม่เคยกดจริง (ทดสอบแล้วเฉพาะว่าไฟล์สำรองกู้ได้ครบ)
3. Dokploy → backend → Deploy ใหม่ 1 รอบ แล้วเปิดเว็บ เช็ครายการงานล่าสุด
4. งานที่ทำหลังเวลาสำรองต้องทำใหม่ (งานจาก ISURVEY ดึงซ้ำได้)

**ค. เซิร์ฟเวอร์หายทั้งเครื่อง** — กู้เครื่องจาก Hostinger backup (ย้อนได้ถึง 7 วัน) แล้วทำข้อ ข. ด้วยไฟล์ล่าสุดจาก R2

## ทดสอบกู้ (ทำแล้ว 24/09/69 — ควรทำซ้ำทุก 3 เดือน)
ทำบนเครื่องพัฒนา ไม่แตะฐานจริง:
1. โหลดไฟล์ล่าสุดจาก bucket `backup` → `gunzip` ได้ไฟล์ขึ้นต้นด้วย `PGDMP`
2. เปิด PostgreSQL 15 ชั่วคราว (zip ของ EnterpriseDB ไม่ต้องติดตั้ง) → `initdb` → `pg_ctl start` (พอร์ตอื่น เช่น 55432 เฉพาะ localhost)
3. สร้างฐาน `restore_test` + `create schema extensions` + `create extension "uuid-ossp"` และ `pgcrypto` ใน schema `extensions`
4. `pg_restore --no-owner --no-acl -n public -d restore_test <ไฟล์>` (กู้เฉพาะตารางของระบบ ส่วนของ Supabase ต้องใช้ image ของ Supabase)
5. นับแถวทุกตาราง public เทียบกับฐานจริง ณ เวลาสำรอง
6. **ลบทุกอย่างทิ้ง** (ไฟล์สำรองมีข้อมูลส่วนบุคคล)
